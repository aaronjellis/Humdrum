## What's new in v0.3.0

A reliability-and-UX pass focused on the two recording paths.

### Meeting recorder

- **Mic picker in Setup.** Pick the input device you're recording with directly from the New Recording window — no more relying on the system default. Previously, if a Bluetooth headset was paired but not on your head, recordings would silently capture nothing. Now you can switch to **MacBook Pro Microphone** (or any other input) without leaving the app.
- **Single-screen Setup.** Quality, Noise filter, Speakers, and Names & terms now all fit without scrolling. Faster glance, faster cut.
- **Speaker-label download with live progress.** Toggling "Label speakers after recording" now downloads the diarization model right in the Setup window, with a real progress bar. **Start Recording** stays disabled until the model is on disk — no more starting a recording only to find Stop hangs while a hidden download chases ~80 MB. Same **Cached** badge style you already see on the Quality tiles.
- **Audio-config resilience.** Mid-recording audio routing changes (AirPlay starting, Bluetooth swap, headphone jack) no longer silently kill the capture. The engine recovers automatically; if it can't, the recording stops cleanly with a status message telling you why.

### Mutter (push-to-talk dictation)

- **Survives audio routing storms.** Same recovery pipeline as the meeting recorder. AirPlay starting, BT swaps, output reroutes — all handled without dropping the dictation. The previous behaviour was: orb appears, audio dies silently, orb hangs for the full 8-second no-speech timeout while you wonder why nothing's transcribing.
- **Fast audio-failure pill.** When audio capture genuinely fails (input device unplugged, sustained system reconfiguration), the orb tears down within ~200 ms with a clear "Audio devices changed — recording stopped" pill instead of hanging.
- **Single-version display.** The About box now shows just "Version 0.3.0" — no more confusing "(0.2.0)" parenthetical from the old auto-bumped build counter.

### Under the hood

If you ever poke at Console for diagnostics, the audio pipeline is now fully instrumented (`audio.first_samples`, `audio.first_audible`, `audio.stalled`, `audio.configChange.*`). Almost every silent-failure mode is now visible in a single `log show` invocation.
